# Docker и PostgreSQL

Основной запуск: PostgreSQL, миграции и API автоответчика. Telegram и каталог
не включены в Compose. Код предыдущего каталога сохранён отдельно.

## Запуск

Установите и запустите Docker Desktop. Скопируйте .env.example в .env,
задайте локально случайные JWT_SECRET и POSTGRES_PASSWORD.
GPT_REPLIES_ENABLED оставьте false для проверки без внешних запросов.

```sh
docker compose up -d --build db migrate api
```

Swagger: http://127.0.0.1:8001/docs
Проверка готовности БД и миграций: /health/ready.
Проверка процесса: /health/live.
API привязан к localhost; PostgreSQL не публикует порт наружу.
Схема обновляется отдельным контейнером migrate до запуска API.
Данные сохраняются в томе postgres_data.

```sh
docker compose stop
```

Не используйте down -v для базы с нужными данными: том будет удалён.

## Перенос из SQLite

Импорт допускает только пустую целевую базу, одинаковую версию миграций
и валидный исходный файл. Перед переносом остановите запись в SQLite,
сделайте резервную копию и примените актуальные миграции к исходной базе.
Источник подключается только для чтения. Скрипт проверяет данные до фиксации,
сохраняет ID, привязки и сообщения. Не перезаписывает непустой PostgreSQL.

Пробный прогон без сохранения:

```sh
docker compose --profile tools run --rm import-data
```

Перенос с сохранением после успешной проверки:

```sh
docker compose --profile tools run --rm import-data python -m scripts.transfer_sqlite --source /input/database.db --apply
```

Не регистрируйте пользователей в целевой БД до переноса. После импорта проверьте
вход и данные через новый API. Изменения после переключения обратно в SQLite
не копируются автоматически; откат требует отдельного плана.

## Интеграционная проверка

scripts/verify_postgres.py проверяет миграции, перенос, автоинкремент ID,
JWT, основной API и сохранённый сервис каталога на отдельной пустой PostgreSQL.
Для защиты от случайного запуска требует ALLOW_DISPOSABLE_POSTGRES_TEST=yes.
Именно этот сценарий выполняется в PostgreSQL-job CI.
Не направляйте его на рабочую базу.
