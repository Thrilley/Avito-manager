# GPT-помощник Avito

## Что готово

В основном приложении только автоответчик, чаты, очередь оператора и вход
владельца. Каталог и Telegram исключены из запуска; прежние файлы и данные
сохранены для восстановления.


Сохранение входящих и исходящих сообщений, ограниченная история (12 сообщений),
GPT-черновик на последнее входящее сообщение, изоляция владельцев и защита от
дубликатов. Черновики не считаются отправленными и не включаются в историю GPT.
Чаты изначально выключены. Сообщение продавца приостанавливает помощника.
При явной просьбе покупателя позвать оператора локальное правило выключает
автоответчик и отмечает human_required=true даже без GPT. GPT при подключении
может распознать дополнительные формулировки просьбы о человеке. Это отметка в API, не уведомление через Telegram.
Обработка повторного message_id с изменённым текстом возвращает 409.
Не поддерживаются вложения; тексты ограничены 4000 символами, ответы — 2000.

## Проверка без ключей

`venv/bin/python -m scripts.demo_autoreply` — демонстрация с временной базой,
без реального GPT и отправок. Шаблонный ответ предназначен только для проверки
потока. Не включается автоматически при сбое настоящего GPT.

Очередь оператора: GET /api/v1/avito/chats?human_required=true, затем история
нужного чата. После обработки владелец сбрасывает human_required и включает
чат через PATCH. Уведомления и отправка ответа оператора в Avito пока не подключены.

## Настройка и локальная проверка

1. Создайте резервную копию базы и выполните `python -m alembic upgrade head`.
   Миграция 0005 добавляет три таблицы, не меняет существующие товары и привязки.
2. Источник SourceAccount с platform=avito должен быть заранее привязан оператором
   к владельцу после проверки принадлежности аккаунта (как для синхронизации).
3. В Swagger войдите обычным JWT владельца. POST
   /api/v1/avito/sources/{source_id}/events принимает нормализованный JSON:
   {"chat_id":"test-chat","message_id":"test-message","direction":"in","text":"Здравствуйте"}.
   Это закрытый операторский API для каркаса, а не webhook Avito.
4. GET /api/v1/avito/chats возвращает локальный id чата; PATCH
   /api/v1/avito/chats/{id} с {"enabled":true,"human_required":false} включает
   создание черновиков. PATCH с enabled=false приостанавливает чат.
5. Только локально настройте OPENAI_API_KEY, OPENAI_MODEL и GPT_REPLIES_ENABLED=true.
   Модель должна поддерживать Responses API и Structured Outputs и быть доступной
   вашему аккаунту. Модель намеренно не выбирается автоматически.
6. POST /api/v1/avito/messages/{локальный message id}/draft создаёт черновик.
   GET /api/v1/avito/chats/{id}/messages показывает сообщения и состояния ответов.
   Списки поддерживают limit (до 100) и offset; порядок от новых к старым.

GPT не получает секреты конфигурации, идентификаторы аккаунтов или весь каталог.
Передаются тексты последних сообщений в OpenAI; store=false отключает сохранение
Response как состояния API, но не является обещанием полного отсутствия хранения
данных у провайдера. Отключите GPT_REPLIES_ENABLED, чтобы прекратить новые запросы.

Цены, наличие, размеры и условия продажи не подтверждаются: каркас ещё не получает
проверенные актуальные данные объявления. GPT предлагает уточнить неизвестные данные. Обычный вопрос о цене или наличии
сам по себе не переводит чат в очередь оператора.
Любой черновик требует просмотра человеком. Инструкции модели не заменяют
программную проверку фактов перед будущей автоматической отправкой.

## Что осталось для настоящего автоответчика

Доступ и права Messenger API Avito, проверка официального контракта и лимитов;
получение/обновление токена; привязка чата к объявлению; загрузка истории;
адаптер webhook (формат, подтверждение доставки и защита входа по реальному
контракту), HTTPS; проверенная свежесть цены/наличия; очередь и отправка ответов.
Официальную страницу Avito не удалось проверить в этой среде, поэтому конкретные
HTTP-методы не предполагаются. AvitoMessenger.send_text всегда явно отказывает.
Даже выставление переменных окружения не включит отправку в Avito.

Генерация синхронная, с таймаутом 30 секунд и ограничением output до 700 токенов.
Уникальный generating на чат блокирует конкурирующие генерации. Если новое
сообщение поступило или чат выключили во время запроса, результат становится
superseded и не сохраняется как текст для отправки. Сбой — failed с обезличенным
кодом; повтор POST возвращает существующее состояние и не тратит деньги снова.
Автоматические повторы не реализованы. После аварии generating может остаться:
оператор должен убедиться, что запрос завершён, и вручную перевести запись в failed.
Перезапуск/повторная генерация старого сообщения через API пока не предусмотрены.

Миграции рабочей базы не запускаются автоматически. Для переноса SQLite/PostgreSQL
обе базы сначала должны иметь одинаковую актуальную схему. Проверки выполняются
в изолированных базах с подставными ответами без реальных запросов и отправок.
