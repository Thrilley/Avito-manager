# Avito Manager

## Локальный запуск

```sh
source venv/bin/activate
python -m pip install -r requirements.txt
python -m alembic upgrade head
python -m uvicorn main:app --reload
```

Swagger: http://127.0.0.1:8000/docs
Перед миграцией существующей базы создайте резервную копию.
Схема больше не создаётся при импорте приложения: используйте Alembic.
DATABASE_URL читается из окружения или локального .env; по умолчанию используется
SQLite database.db в папке проекта, независимо от текущей папки терминала.
Для PostgreSQL задайте URL с драйвером postgresql+psycopg и выполните миграции.
Это создаёт схему PostgreSQL, но не переносит туда записи SQLite.
Перенос записей будет отдельным этапом с проверкой данных.

## Каталог

Новые адреса: /api/v1/listings, /api/v1/listings/{id}, /api/v1/listings/{id}/status.
Старые адреса сохранены. GET каталога поддерживает q, brand, size, condition,
status, price_min, price_max, sort, order, limit (1–100), offset.
Цена в JSON передаётся точной десятичной строкой, например "15000.00".
condition: new/used; status: active/reserved/sold/archived; валюта RUB.
Ручные товары могут не иметь brand/size/condition; PATCH позволяет очищать их null.
Таблица external_listing подготовлена для привязки к источнику, но внешние
синхронизация и публикация ещё не реализованы.
Все маршруты каталога требуют Bearer-токен и ограничены владельцем.

План дальнейших этапов: docs/PLAN.md.

## Вход и права

POST /api/v1/auth/register: JSON username и password (12–128 символов).
POST /api/v1/auth/login: те же поля; ответ access_token, срок 30 минут.
В Swagger нажмите Authorize и вставьте access_token. Пароли и токены не
отправляйте в чат. GET /api/v1/auth/me проверяет вход.
GET /api/v1/auth/users доступен только администратору; чужой каталог даже
администратору не открывается. Регистрация всегда создаёт обычного пользователя.
Старые URL тоже требуют входа. Старые товары без владельца скрыты, но сохранены.
После регистрации своего аккаунта назначьте ему старые товары локально:

```sh
python -m scripts.manage_user YOUR_USERNAME --claim-legacy
```

Для локального назначения администратора добавьте --admin.
Если аккаунта ещё нет, пароль вводится скрыто в терминале.
JWT_SECRET хранится в .env или переменной окружения; без ключа вход возвращает
503. Токен действует 30 минут; повторный вход выдаёт новый токен. Блокировка
пользователя в базе немедленно запрещает доступ. Refresh/logout ещё не реализованы.
До внешнего размещения нужны HTTPS и ограничение частоты регистрации/входа.
Технические источники: https://pyjwt.readthedocs.io/en/stable/usage.html,
https://argon2-cffi.readthedocs.io/en/stable/api.html.

## Синхронизация (подготовленный механизм)

Механизм синхронизации принимает нормализованные страницы через CatalogSource.
Только полный успешный снимок изменяет каталог: добавляет товары, обновляет
название/цену/доступное описание, сохраняет ручные бренд/размер/состояние/статус.
Неизвестный статус источника по умолчанию создаёт archived, а не active.
Исчезнувшие объявления отмечаются source_present=false; товары не удаляются.
source_data хранит нормализованный снимок, включая состояние источника.
Будущий бот должен проверять одновременно локальный статус и доступность
источника, а не считать локальный active доказательством наличия на Avito.
Аккаунты источника привязывает оператор после проверки принадлежности:
публичного API присвоения произвольного Avito account_id нет.

GET /api/v1/sources и /{id}/runs показывают только источники текущего владельца.
POST /api/v1/sources/{id}/sync пока отвечает 503: HTTP-адаптер Avito выключен,
поскольку официальная схема API и права аккаунта пока не подтверждены.
Это не подключённый Avito API и не рабочая выгрузка с Avito.
Реальных запросов, публикаций и скрейпинга нет.

Уникальный running-запуск блокирует параллельный импорт по одному аккаунту.
После аварийной остановки процесса оператор должен убедиться, что worker
остановлен, и перевести зависший running-запуск в failed перед повтором.
Автоматические повторы, лимиты API, расписание и worker добавляются с HTTP-адаптером.
Тесты используют синтетический источник без секретов и внешних запросов.

## Telegram-бот владельца

Бот запускается отдельно и читает общий локальный каталог через сервисный слой.
На этом этапе это личный бот владельца; публичный каталог покупателей и
несколько независимых ботов будут отдельным этапом.

1. Локально добавьте TELEGRAM_BOT_TOKEN в .env (через BotFather).
2. Запустите `python -m app.bot.main` из папки проекта с активированным venv.
3. В Swagger войдите и выполните POST /api/v1/telegram/link-code.
4. В личном чате с ботом отправьте /link КОД. Код действует 10 минут и однократно.
5. Откройте /catalog, /search Nike, /filter brand=Nike size=42 price_max=20000.
   Значения с пробелами: /filter brand="Raf Simons".
6. /item ID открывает карточку. /add принимает JSON товара, например:
   /add {"title":"Nike","description":"Кроссовки","price":"15000","size":"42"}

Команды не выполняются в группах. Карточки выводят обычный текст, без HTML.
Каталог показывает active-товары владельца, для внешних товаров дополнительно
проверяет наличие и нормализованный catalog_status источника. Неизвестный,
закрытый или исчезнувший источник скрывается. Ручные товары без источника доступны.
DELETE /api/v1/telegram/binding отзывает привязку и неиспользованные коды.
Один Telegram-пользователь соответствует одному аккаунту владельца и наоборот.
При повторной привязке сначала отзовите существующую через API.
Фильтры хранятся в памяти процесса; после перезапуска используйте /catalog.
Фотографии, кнопки покупки, публичный магазин и публикация в каналы ещё не реализованы.
Не запускайте два polling-процесса с одним токеном.
Документация библиотеки: https://docs.python-telegram-bot.org/en/latest/telegram.ext.application.html.

## Кнопки и пошаговый ввод

После обновления перезапустите единственный процесс бота и отправьте /start.
Появятся кнопки «Каталог», «Поиск», «Фильтры», «Добавить товар».
Добавление запрашивает название, описание (до 2500 символов), цену,
бренд, размер и состояние. Необязательные поля можно пропустить.
Перед сохранением показывается карточка с кнопками «Сохранить» и «Отмена».
/cancel отменяет ввод; /add без JSON начинает тот же пошаговый сценарий.
Старый /add с JSON поддерживается для совместимости.
В каталоге кнопки «Открыть» открывают карточки; страницы листаются кнопками.
Кнопка «Фильтры» по очереди спрашивает бренд, размер, границы цены и состояние.
Черновики хранятся в памяти, истекают через 30 минут и теряются при перезапуске.
Один повторный клик по сохранённой карточке не создаёт второй товар.
Каждое сохранение заново проверяет действующую привязку и владельца.

## Управление товарами в боте

Кнопка «Мои товары» и /my показывают все собственные товары, включая проданные,
забронированные, архивные и записи со старыми статусами.
В карточке доступны «Редактировать» и «Изменить статус».
Редактирование по очереди запрашивает поля; «Оставить» сохраняет текущий текст,
а «Пропустить» очищает необязательные бренд, размер или состояние.
Изменения применяются после проверки карточки и нажатия «Сохранить».
Статус выбирается отдельно: «В наличии», «Забронирован», «Продан», «В архиве».
Редактирование текста не меняет статус. Все действия заново проверяют владельца.
Это локальные изменения: запросы публикации/редактирования Avito не выполняются.
Для импортированных товаров синхронизация может вновь обновить название,
описание и цену; ручные бренд/размер/состояние/статус сохраняются.

## Docker и PostgreSQL

Конфигурация: compose.yaml и Dockerfile. Инструкция переключения с SQLite,
пробного переноса и запуска одного экземпляра бота: docs/DOCKER.md.
Docker-API использует порт 8001 и отдельную PostgreSQL-базу;
действующая локальная SQLite автоматически не меняется.
GET /health/live проверяет процесс, GET /health/ready — подключение и миграции.
