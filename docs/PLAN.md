# Avito-manager: аудит и план

## Исходное состояние
FastAPI, SQLAlchemy 2, Pydantic 2; SQLite database.db. Существуют CRUD,
поиск, фильтры и сортировка. Разделение router/service/model сохраняем.
Нет миграций, конфигурации окружения, авторизации, бота и интеграций.
Маршруты используют одновременно /listing и /listings; старые URL нужно
сохранить как совместимые алиасы при переходе на /api/v1/listings.

## Этап 1 — исправления
Исправлены titile в обновлении и Python or в SQL-поиске.
Поиск без результатов возвращает пустой каталог.
Добавлены проверки положительной конечной цены, непустого названия,
статусов active/reserved/sold/archived и явного null в PATCH.
Добавлены изолированные тесты без изменения database.db.
Проверка: venv/bin/python -m unittest discover -s tests -v.

## Этап 2 — каталог и PostgreSQL
Конфигурация DATABASE_URL из окружения, Alembic, зафиксированные зависимости.
Product: название, описание, Decimal-цена/валюта, бренд, размер, состояние,
статус, изображения, время создания/обновления, владелец.
ExternalListing: площадка, аккаунт, внешний ID, ссылка, внешний статус,
время последней успешной синхронизации; уникальность площадка+аккаунт+ID.
Существующие записи переносятся как ручные товары. Перед переносом — резервная
копия SQLite; миграция не должна удалять или заменять существующую базу.
Пагинация, поиск, фильтры и сортировка объединяются в один каталог.

## Этап 3 — доступ
Пользователи, хеширование паролей, JWT с ограниченным сроком действия,
роли и проверка владельца. Привязка Telegram по одноразовому коду.
Каждый бот/аккаунт видит только разрешённый ему каталог.

## Этап 4 — Avito
До реализации конкретных HTTP-методов проверить официальную документацию,
доступные поля, права аккаунта и ограничения. Не предполагать поддержку
создания, изменения объявлений, фотографий или произвольных чужих каталогов.
Адаптер сообщает доступные операции. Локальный PostgreSQL служит каталогом
для ботов, Avito — внешним источником данных.
Синхронизация: пагинация, идемпотентный upsert, блокировка параллельных запусков,
повторы с задержкой, обработка лимитов, журнал запусков и сохранение последнего
успешного снимка. Исчезновение объявления учитывается лишь после полного
успешного обхода; сбой API не удаляет товары.
Разделить поля источника и ручные поля (бренд/размер/состояние), чтобы импорт
не перезаписывал ручные дополнения. Недоступность API не блокирует каталог.

## Этап 5 — Telegram и публикация
Бот обращается к сервису каталога: страницы, поиск, фильтры, карточки и ссылки.
Владелец может вручную добавлять товары. Публикации в Telegram и Avito —
отдельные задания с состояниями и защитой от повторного выполнения.
Для неподдерживаемой операции возвращать явную ошибку без имитации успеха.
Токены читаются из окружения, не попадают в репозиторий или логи.

## Этап 6 — эксплуатация
Docker Compose (API, PostgreSQL, worker, bot), health checks, структурированные
логи, CI, инструкции подключения. Тесты API, прав, миграций, повторных импортов,
ошибок источника, публикаций и PostgreSQL. Внешние подключения отдельно
проверяются с настоящими правами; локальные тесты используют подставной адаптер.
