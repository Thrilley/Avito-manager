# Avito Manager · помощник продавца

Backend на **FastAPI и SQLAlchemy** для хранения переписки, подготовки
ответов покупателям и передачи разговора оператору. PostgreSQL, JWT,
миграции Alembic и Docker Compose.

> Учебный backend-проект с проверяемой локальной демонстрацией. Интеграция
> с реальным Messenger API Avito и отправка сообщений не подключены.
> GPT создаёт только черновики для просмотра человеком.

## Возможности

- Регистрация, вход и JWT с ограниченным сроком действия; изоляция данных владельцев.
- Приём нормализованных тестовых событий, история сообщений и защита от дублей.
- Передача чата оператору по просьбе покупателя и приостановка помощника.
- Опциональные GPT-черновики через OpenAI Responses API, ограниченная история
  и проверка структуры ответа.
- Защита от параллельной генерации и устаревшего ответа при новом сообщении.
- PostgreSQL для Docker, SQLite для локальной разработки.
- Миграции, проверки готовности API, тесты и CI.

Каталог товаров и Telegram-бот сохранены как предыдущий этап проекта в
`app/legacy_app.py`. Они проверяются регрессионными тестами, но не включены
в основной `main:app`. Инструкция: [предыдущий каталог](docs/LEGACY_MANAGER.md).

## Быстрая демонстрация — без ключей и аккаунта Avito

Требуется Python **3.14**.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m scripts.demo_autoreply
```

На Windows активируйте `.venv\Scripts\Activate.ps1` вместо команды `source`.
Демонстрация использует временную базу и подставной генератор: показывает
обычный ответ и передачу оператору. Внешних запросов, отправок и изменений
рабочей базы нет. Это самый короткий способ посмотреть проект.

## Локальный API

```bash
cp .env.example .env
```

Сгенерируйте JWT-ключ и вставьте результат **только в свой `.env`**:

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

Укажите `JWT_SECRET=...`, затем:

```bash
python -m alembic upgrade head
python -m uvicorn main:app --reload
```

Swagger: [localhost:8000/docs](http://127.0.0.1:8000/docs).
По умолчанию создаётся SQLite в папке проекта. Перед миграцией существующей
базы сделайте резервную копию. Импорт приложения сам не меняет схему.

1. `POST /api/v1/auth/register`: создайте username и пароль от 12 символов.
2. `POST /api/v1/auth/login`: получите access_token.
3. В Swagger нажмите **Authorize** и вставьте токен без префикса Bearer.
4. Для тестовых событий источник сначала привязывается к владельцу оператором;
   пошаговая инструкция — [работа с чатами и черновиками](docs/AVITO_REPLIES.md).

## Docker и PostgreSQL

В `.env` задайте случайные `POSTGRES_PASSWORD` и `JWT_SECRET`. Затем:

```bash
docker compose up -d --build db migrate api
```

Swagger: [localhost:8001/docs](http://127.0.0.1:8001/docs).
База хранится в Docker volume; порт PostgreSQL наружу не открывается.
Миграции выполняются до старта API. Основной Compose запускает только
PostgreSQL, миграции и API, без Telegram-бота.

```bash
docker compose stop
```

`docker compose down -v` удалит данные базы. Перенос SQLite и проверка
пустого PostgreSQL: [инструкция Docker](docs/DOCKER.md).

## Настройки

| Переменная | Назначение |
| --- | --- |
| `JWT_SECRET` | Обязательный для входа локальный ключ, минимум 32 байта |
| `DATABASE_URL` | URL SQLite или PostgreSQL; локально по умолчанию SQLite |
| `POSTGRES_PASSWORD` | Пароль PostgreSQL для Compose |
| `API_PORT` | Локальный порт Compose API, по умолчанию 8001 |
| `GPT_REPLIES_ENABLED` | `false` по умолчанию; включает обращения к OpenAI |
| `OPENAI_API_KEY` | Ключ OpenAI, нужен только при включённом GPT |
| `OPENAI_MODEL` | Модель с Responses API и Structured Outputs |

Настройки Docker-подключения к БД передаются отдельно через `DATABASE_HOST`,
`DATABASE_PORT`, `DATABASE_USER`, `DATABASE_PASSWORD` и `DATABASE_NAME`.
Секреты, переписка, базы и резервные копии не входят в репозиторий или образ.

При включении GPT тексты последних сообщений передаются в OpenAI. `store=false`
не является обещанием отсутствия любого хранения данных провайдером.
По умолчанию GPT отключён. Не включайте его для реальной переписки без решения
владельца аккаунта и подходящих условий обработки данных.

## Архитектура

```text
main.py                 — основное приложение автоответчика
app/routers/            — HTTP-маршруты и проверка доступа
app/services/           — состояния чатов, черновиков и передача оператору
app/integrations/       — GPT и отключённые адаптеры Avito
app/core/               — хеширование паролей и JWT
app/models.py           — модели SQLAlchemy
app/legacy_app.py       — предыдущий каталог и Telegram API
app/bot/                — предыдущий Telegram-бот
migrations/             — версии схемы Alembic
scripts/                — офлайн-демо, перенос и PostgreSQL-проверка
tests/                  — проверки поведения и регрессий
```

Событие → сохранение сообщения → проверка необходимости оператора →
подготовка черновика → просмотр человеком. Отправка в Avito выключена.

## Тесты

```bash
python -m unittest discover -s tests -v
```

Тесты работают на изолированных базах с подставными провайдерами. CI проверяет
SQLite, миграции и отдельную временную PostgreSQL-базу. Проверяются доступ,
повторные события, состояния генерации, передача оператору, перенос данных
и сохранённый каталог. Интеграционный сценарий PostgreSQL отказывается
работать с непустой базой.

## Ограничения и следующие шаги

- Нет подтверждённого подключения к Avito, webhook и реальной отправки.
- Не реализованы проверка свежести цены/наличия и автоматическая отправка.
- Генерация синхронная; worker, расписание и восстановление зависших заданий
  потребуются для эксплуатации.
- Нет refresh-токенов, публичной регистрации с антиспамом и ограничения частоты
  входа. Перед внешним размещением нужны HTTPS и дополнительные меры доступа.
